# HealingManifest — V1 Spec

## Purpose
The HealingManifest is an immutable audit record generated whenever a RepairPlan is executed.

It exists to provide traceability, accountability, and governance.

---

## When It Is Created
- Generated by Aegis_Surgeon
- Created before any commit step
- One manifest per execution attempt (success or failure)

---

## Required Contents
A HealingManifest must record:

- Timestamp
- RepairPlan (verbatim)
- ExecutionResult
- ValidationResult
- Component versions (Inspector, Consultant, Surgeon)
- Execution mode (sandbox / commit)
- Operator (human or system)

---

## Immutability Rules
- HealingManifests are append-only
- Never modified after creation
- Never deleted

---

## Explicit Non-Goals (V1)
The HealingManifest does NOT:
- Enforce approvals
- Trigger rollbacks
- Store raw data
- Make decisions
